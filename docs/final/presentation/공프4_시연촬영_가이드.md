# 공프4 기말 시연 영상 촬영 가이드

> 발표자료는 `공프4_기말발표_PPT.pptx`(기준본)이며 영상 자리는 **14장**입니다. 백업판도 같은 14장입니다.

목표: PPT 14장에 넣을 **약 60초** 화면 녹화 1개. 영상에는 **소리를 넣지 않고**, 발표 녹음 때 영상이 나오는 동안 대본 14장을 말합니다(소리가 겹치지 않게).
내용: 실적 입력 → 긴급 판정 → **현장 작업지시(승인 전)** → 후보 비교(추가근무 포함) → 승인 → 계획 v2 → **현장 작업지시(승인 후)**. 아래 수치는 자동 테스트(`tests/integration/test_demo_overtime_option.py`)로 고정된 값이고, 작업지시 내용은 같은 시연 데이터로 API를 직접 호출해 확인했습니다.

이 영상이 보여주는 것과 보여주지 않는 것:
- 보여줌: 승인하면 계획 버전이 바뀌고, **현장 단말이 받는 작업지시가 실제로 바뀐다**.
- 보여주지 않음: 현장이 그 지시대로 일한다는 것. 이건 810회 실험(가상 현장이 작업지시 API를 읽고 그대로 실행)과 자동 테스트로 확인한 내용이며, 대본도 그렇게 말합니다.

## 1. 준비 (녹화 전 1회, 약 5분)

```bash
cd project4_manufacturing_logic
git pull origin main
python -m pip install -e ".[dev]"

# DB를 중간발표 시작 상태로 초기화 (서버가 꺼진 상태에서)
python -m production_control.demo.init_db --reset

# 터미널 1: API, 추가근무 후보 켜기
PRODUCTION_CONTROL_OVERTIME_END=19:00 \
python -m uvicorn production_control.api.runtime:app --host 127.0.0.1 --port 8000

# 터미널 2: 관리자 화면, 시연 시각 고정 (10/22 13:17)
PRODUCTION_CONTROL_DEMO_TIME=2026-10-22T13:17:00+09:00 \
python -m streamlit run src/production_control/ui/overview.py --server.address 127.0.0.1
```

- 브라우저: `http://127.0.0.1:8501`, 창 너비 1600px 이상, 확대 100%. 사이드바는 접어 두면 화면이 넓어집니다(왼쪽 위 `«`).
- 두 환경변수를 빼먹으면 안 됩니다. `OVERTIME_END`가 없으면 추가근무 후보가 안 나오고, `DEMO_TIME`이 없으면 실제 날짜(11월) 기준이라 모든 LOT가 지연으로 보입니다.
- 다시 찍을 때: 두 서버를 끄고 `init_db --reset`부터 반복합니다(승인 결과가 DB에 남기 때문).

## 2. 녹화 순서와 시간 (총 약 60초)

**브라우저 탭 3개를 미리 열어 둡니다.**
- 탭 1: 관리자 화면 `http://127.0.0.1:8501`
- 탭 2 (작업지시, 지금): `http://127.0.0.1:8000/work-orders?as_of=2026-10-22T13:17:00%2B09:00`
- 탭 3 (작업지시, 오늘 17시): `http://127.0.0.1:8000/work-orders?as_of=2026-10-22T17:00:00%2B09:00`

탭 2·3은 JSON 글자 화면입니다. 크롬은 위쪽 `보기 좋게 표시(Pretty-print)`를 켜고, 확대를 125–150%로 키우면 잘 보입니다. 480분 입력 전에는 작업지시가 비어 있는 것이 정상입니다(작업이 예상 시간을 넘겨 남은 시간을 묻는 중이라서). 그래서 탭 2·3은 녹화 중에 **새로고침(F5)** 해서 보여 줍니다.

JSON에서 묶음 이름은 내부 번호로 나옵니다: `LOT-101`=LOT-001, `LOT-102`=LOT-002, `LOT-103`=LOT-003. 제품은 `LOT-103-U16`처럼 나옵니다.

| 시간 | 화면 | 동작 | 확인할 값 |
|---|---|---|---|
| 0–4초 | 탭 1 **생산현황** | 그대로 둠 | 현재 승인 계획 **v1**, 긴급 LOT **0** |
| 4–14초 | 탭 1 **현장 실적 입력** | LOT `LOT-001`, Unit `U030` 선택 → `예상 잔여 작업시간 입력/수정` 펼침 → **480** 입력 → `예상 잔여 작업시간 반영` 클릭 | U030 현재 공정 튜닝, 작업 중 |
| 14–18초 | 탭 1 **생산현황** | 지표 확인 | 긴급 LOT **1** |
| 18–24초 | **탭 2** | F5 | `"plan_version": 1`, 첫 지시 `LOT-103-U16` / `FINISH_ASSEMBLY`(LOT-003 마무리 조립) |
| 24–36초 | 탭 1 **재계획** | 빨간 문구 확인 → `재계획안 계산·비교` 클릭 → 순위표로 스크롤 | "LOT-001 … 4시간 57분 늦습니다", 1위 3개(EDD·Slack·CR + 추가근무) **2시간 57분 / 추가 가동 2시간** |
| 36–44초 | 탭 1 재계획(아래) | 승인 버튼 `EDD · 납기가 가까운 LOT 우선 + 추가근무(~19:00, 10/22) 재계획안 승인` 클릭 | 초록 안내 "승인 완료 · 새 승인계획 v2" |
| 44–48초 | 탭 1 **생산현황** | 지표 확인 | 현재 승인 계획 **v2**, 긴급 LOT **1**(여전히 긴급) |
| 48–54초 | **탭 2** | F5 | `"plan_version": 2`, 첫 지시 `LOT-103-U11` / `FINAL_TEST`(LOT-003 최종 성능시험) |
| 54–60초 | **탭 3** | F5 | 17:00–17:30 `FINAL_TEST` 지시(추가근무 시간대 작업). 승인 전이었다면 비어 있음 |

순위표는 "공동 1위"로 세 줄이 나옵니다. 어느 것을 골라도 지연은 같고, 대본·PPT는 EDD + 추가근무를 승인하는 것으로 맞춰 두었습니다. 기본 선택은 첫 줄(EDD)입니다. 다른 줄이 선택돼 있으면 순위표 아래 `상세 확인할 재계획안` 상자에서 EDD를 고른 뒤 승인합니다.

## 3. 주의할 점

- 숫자가 위 표와 다르면 DB 초기화나 환경변수를 의심합니다. 승인 후에도 LOT-001은 긴급(177분 지연)으로 남는 것이 정상입니다. "추가근무로 해결됐다"고 말하지 않습니다.
- 마우스는 천천히, 클릭 전 0.5초 멈춤. 계산·승인 직후 화면이 다시 그려지는 1–2초는 자르지 않아도 됩니다.
- 녹화 해상도 1920×1080, 30fps, MP4(H.264). OBS 또는 Windows `Win+Alt+R`, macOS `Cmd+Shift+5`.
- 개인 정보(브라우저 북마크·다른 탭·알림)가 화면에 나오지 않게 전체화면(F11) 권장.

## 4. PPT에 넣기

PowerPoint에서 14장의 재생 아이콘·회색 상자를 지우고 `삽입 → 비디오 → 이 디바이스`로 MP4를 넣은 뒤, `재생 → 시작: 자동 실행`으로 설정합니다. 그래야 슬라이드 쇼를 녹화할 때 14장에 들어가면 영상이 저절로 나옵니다. 영상 위치는 회색 상자 자리(가로 가운데, 제목 아래)에 맞추면 됩니다. 영상이 65초를 넘으면 `비디오 트리밍`으로 앞뒤를 자릅니다.

## 5. 대본 14장과 화면 맞추기

대본 14장은 위 녹화 순서와 같은 차례로 말합니다: 480분 입력 → 긴급 → 작업지시 "마무리 조립" → 후보·순위 → EDD 추가근무안 승인 → 버전 2 → 작업지시 "최종 성능시험"과 17시 이후 작업. 보통 속도로 약 40초 분량이라 영상(약 60초)보다 짧습니다. 화면에 맞춰 천천히 말하고, 그래도 말이 먼저 끝나면 영상 끝까지 기다렸다가 넘깁니다.
